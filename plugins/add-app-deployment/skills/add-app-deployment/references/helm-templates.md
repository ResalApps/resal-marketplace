# Helm Templates Guide

## How to Generate Templates

All app Helm templates follow an identical pattern generated by `scripts/update-resal-apps-templates/`. The only difference between apps is the app name in template helper references.

**Best approach:** Read the templates from an existing reference app and replace the app name.

### Reference App

Use `apps/resal-admin/resal-admin-frontend/` as the reference for frontend apps, or any app in `apps/core/` for backend apps. Read each template file from the reference and replace every occurrence of the reference app name with the new app name.

For example, if the reference is `resal-admin-frontend` and the new app is `my-new-app`:
- `resal-admin-frontend.name` becomes `my-new-app.name`
- `resal-admin-frontend.labels` becomes `my-new-app.labels`
- `resal-admin-frontend.chart` becomes `my-new-app.chart`
- `resal-admin-frontend.selectorLabels` becomes `my-new-app.selectorLabels`
- `resal-admin-frontend.serviceAccountName` becomes `my-new-app.serviceAccountName`
- `resal-admin-frontend.albCertificateARN` becomes `my-new-app.albCertificateARN`
- `resal-admin-frontend.albGroupName` becomes `my-new-app.albGroupName`

### Template Files Required (11 total)

1. **`_helpers.tpl`** - Template functions: name, chart, labels, selectorLabels, serviceAccountName, albCertificateARN, albGroupName
2. **`deployment.yaml`** - Deployment with main container + optional sidecar, configmap envFrom, 1Password secret env vars
3. **`service.yaml`** - ClusterIP/NodePort service
4. **`ingress.yaml`** - ALB ingress with SSL redirect, Cloudflare proxied, WAF support
5. **`configmap.yaml`** - ConfigMap with key validation (uppercase + underscore pattern)
6. **`hpa.yaml`** - HPA with CPU and memory targets
7. **`serviceaccount.yaml`** - Optional service account
8. **`onepassworditem.yaml`** - 1Password items for secrets (excludes POSTGRES_PASSWORD, REDIS_PASSWORD)
9. **`volumes-onepassworditem.yaml`** - 1Password items for volume-mounted secrets
10. **`postgresql-onepassworditem.yaml`** - PostgreSQL-specific 1Password item
11. **`NOTES.txt`** - Post-install notes showing access URLs

### Key Rules

- Every template starts with: `# Code generated by update-resal-apps-templates; DO NOT EDIT.`
- `_helpers.tpl` uses comment block: `{{/* Code generated by update-resal-apps-templates; DO NOT EDIT. */}}`
- Every template ends with: `# vim: syntax=yaml ft=helm nospell`
- The dev ACM certificate ARN is hardcoded in `_helpers.tpl`: `arn:aws:acm:us-east-2:244122818208:certificate/17a0e0c3-32f5-4718-b66a-88cc06fd7b2c`
- ALB group names default to the environment name: `dev`, `stage`, `prod`

## Values File Templates

### values-{env}.yaml Structure

```yaml
extraInfo:
  name: "GitHub Repository:"
  value: "https://github.com/ResalApps/{GITHUB_REPO}"

environment: "{ENV}"              # dev, stage, prod
relatedApps: "{RELATED_APPS}"    # store, core, admin, etc.
component: "{COMPONENT}"         # frontend, backend, api

replicaCount: 1

image:
  repository: "882222437772.dkr.ecr.us-east-2.amazonaws.com/{ECR_PATH}"
  tag: "{ENV}.1.1.0"

resources:
  requests:
    cpu: "{CPU}"
    memory: "{MEMORY}"

sidecars:
  - name: "{APP_NAME}-sidecar"
    enabled: false
    command: ["sh", "-c", "python -m uvicorn app.main:app --host 0.0.0.0 --port 8888"]

service:
  enabled: true
  type: NodePort
  port: 80
  containerPort: {CONTAINER_PORT}  # 3000 for frontends, 8080 for backends

serviceAccount:
  create: false
  automount: true
  annotations: {}
  name: ""

strategy:
  enabled: true
  type: RollingUpdate
  rollingUpdate:
    maxSurge: "25%"
    maxUnavailable: "25%"

autoscaling:
  enabled: false
  minReplicas: 1
  maxReplicas: 3
  targetCPUUtilizationPercentage: 80
  targetMemoryUtilizationPercentage: 80

configmap:
  create: true  # or false if no configmap needed

ingress:
  enabled: true
  className: "alb"
  annotations:
    alb:
      groupName: ""
      listenPorts: ""
      scheme: internet-facing
      healthCheckPath: ""
      sslRedirect: true
      certificateARN: ""  # auto-selected for dev, must specify for stage
      wafv2AclArn: ""
    cloudflare:
      proxied: true
  hosts:
    - host: "{HOSTNAME}"
      paths:
        - path: /
          pathType: Prefix

postgresql:
  enabled: false
  # Include full postgresql config even if disabled — see Bitnami Images section below

onepassword:
  vault: "{ENV}-cluster"  # dev-cluster or stage-cluster
  secrets: {}  # or key-value pairs for 1Password secrets
```

### config-{env}.yaml Structure

```yaml
image:
  tag: "{ENV}.1.1.0"

configmap:
  create: true
  data:
    KEY_ONE: "value1"
    KEY_TWO: "value2"

onepassword:
  vault: "{ENV}-cluster"
  secrets: {}
  volumes: []
```

### Chart.yaml

```yaml
apiVersion: v2
name: {APP_NAME}
description: A Helm chart for Kubernetes
type: application
version: 0.1.0
appVersion: "1.16.0"

dependencies:
  - name: postgresql
    alias: postgresql
    condition: postgresql.enabled
    repository: https://charts.bitnami.com/bitnami
    version: "^16.7.4"
```

## Bitnami Images

Bitnami has migrated many Docker images from `docker.io/bitnami/` to `docker.io/bitnamilegacy/`. When enabling PostgreSQL, Redis, or other Bitnami-based dependencies, always use `bitnamilegacy/` as the image repository.

**Current known `bitnamilegacy` images used across Resal infrastructure:**

| Image | Repository | Example Tag |
|-------|-----------|-------------|
| PostgreSQL | `bitnamilegacy/postgresql` | `17.6.0-debian-12-r4` |
| Redis | `bitnamilegacy/redis` | Check Docker Hub for latest |
| OS Shell (init container) | `bitnamilegacy/os-shell` | (used for volumePermissions) |

**When enabling PostgreSQL in values-{env}.yaml:**

```yaml
postgresql:
  enabled: true
  global:
    security:
      allowInsecureImages: true
    defaultStorageClass: "gp3"
    postgresql:
      service:
        ports:
          postgresql: 5432
  image:
    registry: docker.io
    repository: bitnamilegacy/postgresql    # NOT bitnami/postgresql
    tag: 17.6.0-debian-12-r4
    pullPolicy: IfNotPresent
  volumePermissions:
    image:
      registry: docker.io
      repository: bitnamilegacy/os-shell    # NOT bitnami/os-shell
  auth:
    enablePostgresUser: false
    username: "{APP_DB_USER}"
    database: "{APP_DB_NAME}"
    onepasswordVault: "{ENV}-cluster"
    existingSecret: "{APP_NAME}-postgresql"
    secretKeys:
      userPasswordKey: "POSTGRES_PASSWORD"
  primary:
    persistence:
      size: 1Gi
```

> **Always verify:** Before deploying, check Docker Hub to confirm the specific image and tag exists under `bitnamilegacy/`. If a new Bitnami chart version moves the image back to `bitnami/`, update accordingly. The Helm chart repository (`https://charts.bitnami.com/bitnami`) remains unchanged regardless of image registry.
